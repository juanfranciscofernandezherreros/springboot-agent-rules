Informe de generación: orders-api

Especificación de entrada: examples/orders.yaml.

Correcto

Proyecto: se generó generated/orders-api con Java 21, Spring Boot 4.0.0, Maven Wrapper, SQL Server, Flyway, Docker Compose y la estructura por capas requerida.
Contrato: se implementaron creación, consulta por id, búsqueda paginada con filtros, PATCH y borrado para /orders.
Calidad: mvnw spotless:apply y mvnw verify finalizaron correctamente; se ejecutaron 3 tests sin fallos.
Validación estática: el validador confirmó pom, wrapper, Java 21, JDBC SQL Server, Flyway, ausencia de H2, Dockerfile, Compose, ddl-auto validate, migración y script de persistencia.

Fallos encontrados

Inicializador SQL Server: la combinación de entrypoint: [bash, -c] y un comando YAML plegado separó los argumentos de sqlcmd. El contenedor intentó conectarse a sí mismo y terminó con código 1. Debe renderizarse el comando completo como un único argumento de bash -c, o evitar bash -c y usar una lista de argumentos directa.
Puerto local: el puerto 1433 del host estaba ocupado. El Compose sí permite sobrescribirlo mediante SQLSERVER_PORT; el arranque con 1435 alcanzó SQL Server, pero quedó detenido por el inicializador.
Healthcheck de la API: el Dockerfile runtime no instala wget, aunque el healthcheck lo usa. El generador debe alinear las utilidades disponibles en la imagen runtime con el comando de healthcheck, por ejemplo instalando wget/curl o usando una comprobación basada en Java.

Mejoras para el generador

  1. Ejecutar docker compose config y comprobar que los comandos de inicialización siguen siendo una única cadena cuando usan un intérprete de shell.
  2. Ejecutar una prueba mínima del healthcheck dentro de la imagen antes de declarar el stack válido.
  3. Detectar puertos host ocupados antes del arranque y escoger un puerto libre conservando el puerto interno y el hostname de servicio.
  4. No marcar la verificación de persistencia como superada hasta crear el registro, consultarlo por SQL y repetir ambas comprobaciones tras recrear los contenedores.
